## 📱 v3.3 更新内容

### 🎯 核心改进

#### 1. 🖥️ 智能DPI适配的窗口大小（1366x768）

**重要说明：**
- **目标尺寸**：1366x768（视觉显示尺寸）
- **实现方式**：根据系统DPI缩放自动调整设置值
- **适用范围**：整个窗口（包括标题栏、边框等所有装饰）

**技术实现：**

```java
// 获取系统DPI缩放比例
double dpiScaleX = transform.getScaleX();  // 例如：1.25 (125%)
double dpiScaleY = transform.getScaleY();

// 计算考虑DPI缩放后的窗口尺寸
int targetWidth = 1366;   // 期望显示的宽度
int targetHeight = 768;   // 期望显示的高度

// 补偿DPI缩放
int windowWidth = (int)(targetWidth / dpiScaleX);   // 1366 / 1.25 = 1092
int windowHeight = (int)(targetHeight / dpiScaleY); // 768 / 1.25 = 614

// 设置窗口尺寸
setSize(windowWidth, windowHeight);
```

**不同DPI下的表现：**

| 系统DPI | 设置尺寸 | 实际显示尺寸 | 说明 |
|---------|---------|------------|------|
| 100%    | 1366x768 | 1366x768 | 无需调整 |
| 125%    | 1092x614 | 1366x768 | 自动补偿 |
| 150%    | 911x512 | 1366x768 | 自动补偿 |
| 200%    | 683x384 | 1366x768 | 自动补偿 |

**优势：**
- ✅ 在任何DPI设置下都保持一致的视觉大小
- ✅ 符合主流笔记本分辨率（1366x768）
- ✅ 不会超出屏幕范围
- ✅ 保持良好的可视区域和操作空间
- ✅ 自动适配，无需手动调整

**控制台输出示例：**
```
[04:16:45] ℹ️  INFO: 系统DPI缩放: 125.0%
[04:16:45] ℹ️  INFO: 设置窗口尺寸: 1092x614 (期望显示: 1366x768)
✅ GUI界面已启动
📏 窗口外部尺寸（包括标题栏和边框）: 1092x614
📏 内容区域尺寸: 1078x577
```

**注意：**
- "窗口外部尺寸" 是程序设置的值（已考虑DPI补偿）
- Windows会自动将其放大到期望的1366x768显示
- 这是整个窗口的大小，包括标题栏和边框

#### 2. 🚀 智能启动策略（双方案降级）

**问题背景：**
- 不同的Android系统和应用可能有不同的启动方式
- 单一启动方法可能在某些情况下失败
- 需要更可靠的启动机制

**解决方案：智能降级策略**

```
启动流程：
┌─────────────────────┐
│   开始启动应用       │
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│ 方法1: am start     │ ← 优先使用（标准、可靠）
│                     │
│ 步骤1: 查询Activity │
│ 步骤2: 启动应用     │
└──────────┬──────────┘
           ↓
      成功？
     ↙     ↘
   是       否
   ↓        ↓
  结束   ┌─────────────────────┐
         │ 方法2: monkey       │ ← 降级方案（兼容性好）
         │                     │
         │ 模拟点击LAUNCHER    │
         └──────────┬──────────┘
                    ↓
                 成功？
                ↙     ↘
              是       否
              ↓        ↓
            结束    启动失败
```

### 🔧 技术实现详解

#### 方法1：am start（优先方案）⭐

**为什么优先？**
- ✅ 更标准、更正式的启动方式
- ✅ 直接调用Activity，效率高
- ✅ 可以指定具体的Activity
- ✅ 错误信息更明确

**实现步骤：**

**步骤1：查询应用的启动Activity**
```bash
adb shell cmd package resolve-activity --brief <package>
```

**输出示例：**
```
com.example.app/.MainActivity
```

**步骤2a：如果找到Activity，使用完整路径启动**
```bash
adb shell am start -n com.example.app/.MainActivity
```

**步骤2b：如果未找到Activity，使用包名启动**
```bash
adb shell am start -a android.intent.action.MAIN \
                   -c android.intent.category.LAUNCHER \
                   -p com.example.app
```

**成功判断：**
- 输出包含 "Starting"
- 输出包含 "Success"
- 没有 "Error" 或 "Exception"

---

#### 方法2：monkey（降级方案）🔄

**什么时候使用？**
- am start 完全失败时
- 无法获取Activity信息时
- 作为最后的备选方案

**命令：**
```bash
adb shell monkey -p <package> -c android.intent.category.LAUNCHER 1
```

**原理：**
- 模拟用户点击桌面图标
- 发送1个LAUNCHER事件
- 系统自动找到合适的Activity

**成功判断：**
- 输出包含 "Events injected"
- 输出包含 ":Dropped"
- 没有 "No activities found" 或 "Security exception"

| 特性 | am start | monkey |
|------|----------|--------|
| **优先级** | ⭐⭐⭐ 高 | ⭐⭐ 低 |
| **可靠性** | ⭐⭐⭐ 高 | ⭐⭐ 中等 |
| **速度** | ⭐⭐⭐ 快 | ⭐⭐ 稍慢 |
| **兼容性** | ⭐⭐ 中等 | ⭐⭐⭐ 高 |
| **精确度** | ⭐⭐⭐ 高 | ⭐⭐ 中等 |
| **错误提示** | ⭐⭐⭐ 清晰 | ⭐⭐ 一般 |
| **适用场景** | 标准应用 | 特殊/老旧应用 |

### 🎨 代码结构

#### 主要方法

```java
// 主入口：智能选择启动方法
private void launchApp(AppInfo app)
    ↓
// 方法1：am start（优先）
private boolean launchWithAmStart(String device, AppInfo app)
    ├── getLaunchActivity()          // 查询启动Activity
    └── executeLaunchCommand()       // 执行启动命令
    ↓ (失败时)
// 方法2：monkey（降级）
private boolean launchWithMonkey(String device, AppInfo app)
```

#### 辅助方法

```java
// 查询应用的启动Activity
private String getLaunchActivity(String device, String packageName)

// 执行启动命令并检查结果
private boolean executeLaunchCommand(String[] adbCommand, String methodName)
```

### 🔍 调试技巧

#### 查看完整的启动日志

```
启动时会输出详细的流程日志：
1. 开始启动的标记
2. 方法1的尝试过程
3. 是否降级的决策
4. 方法2的执行情况
5. 最终结果
6. 结束标记
```

#### 分析启动失败原因

```
根据日志判断：
- 如果方法1失败但方法2成功 → 应用可能需要特殊处理
- 如果两种方法都失败 → 应用可能未正确安装
- 如果查询不到Activity → 应用可能没有LAUNCHER
```
